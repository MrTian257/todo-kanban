# PRD：todo-kanban 泳道看板重构

> 版本：v1.1 ｜ 日期：2026-09-03 ｜ 状态：**已实施**（v2.0.0 提交 a31e4de + v2.1 排序持久化）
> 关联文档：docs/软件设计文档.md（v1.2）、docs/01-design/*（已同步更新，schema v6）

## 1. 目标 / 非目标

### 目标
- 将看板由「艾森豪威尔四象限」**替换**为「泳道模式」：**列 = 泳道，行 = 待办**
- 默认泳道三列：**待办 / 进行中 / 已完成**（分别绑定状态 todo / doing / done）
- 支持**按项目维度自定义泳道**：增删、改名、排序；新增泳道必须绑定一个状态（一个状态可拆多个泳道）
- **跨泳道拖拽** = 修改待办归属（泳道 + 状态联动）并落库；泳道内拖拽排序亦落库（sortOrder 0..n，重载保留）
- 数据模型升级 **SQLite schema v4 → v6**（`todos.swimlane_id`、`projects.swimlanes`、`todos.sort_order`），存量数据无损迁移
- 保持既有能力不变：git 分支体系、提交记录双通道关联（时间窗/标记）、GitLab 远端分支、Markdown 备注、主题皮肤

### 非目标
- ❌ 不做多泳道维度（如同时按人员 × 状态分组）——仅状态单维度
- ❌ 不删除 `quadrant` 字段（仅数据兼容保留，UI 不再展示/编辑），不做字段清理任务
- ❌ 不做泳道级权限/协作（单机单用户语义不变）
- ❌ 不改变 `/focus`、`/todos`、`/settings` 等其它页面行为
- ❌ 不引入数据库字段级加密（Token 明文策略维持现状）

## 2. 用户故事

- 作为开发者，我打开项目看板时能直观看到待办处于哪个阶段（待办/进行中/已完成），**每个待办占一行**，一目了然。
- 作为开发者，我把一张卡片从「待办」拖到「进行中」，它就自动变为进行中状态且**立即持久化**，刷新后不丢失。
- 作为团队负责人，我希望按自己的流程**自定义泳道**（如新增「待评审」「已发布」列、删掉不需要的列、改列名、调整列顺序），适配真实发布流程。
- 作为老用户，升级到新版本后我的既有项目/待办**原样可见**（自动迁移进默认泳道），无需手动处理。
- 作为使用者，我在详情页修改待办时能直接**选择所属泳道**，且状态随之正确联动。
- 作为开发者，我误删了泳道——该泳道下的待办自动归入同状态其它泳道，**数据不丢**。

## 3. 方案概述

### 3.1 领域模型
- 新增 **Swimlane**：`{ id, name, status: todo|doing|done, sortOrder }`，存于 `projects.swimlanes`（JSON 列）
- 默认泳道（新项目预置 / normalize 兜底）：待办(`swim-todo`) / 进行中(`swim-doing`) / 已完成(`swim-done`)
- **状态是唯一事实源**：泳道只是状态的"分组容器"，一个状态可有多个泳道（如「已完成 / 已发布」都绑 done）
- Todo 新增 `swimlaneId`（v5 列）；`quadrant` 保留仅兼容

### 3.2 交互
- **布局**：泳道列横向排列（自适应/可横向滚动），列头 = 泳道名 + 计数 + 操作；列内待办纵向排列成行
- **拖拽**（dnd-kit）：泳道内重排 → `commitOrder`；跨泳道 → `patchTodo({ swimlaneId, status })`（status = 目标泳道绑定状态），均经 store 落库
- **泳道管理**（看板「管理泳道」对话框）：增删 / 改名 / 拖拽排序；删除须二次确认，其下待办迁移至同状态剩余第一个泳道
- **详情页**：象限按钮替换为「所属泳道 Select」（按状态分组），切换泳道同步表单 status；新建支持 `?swimlane=` 预选
- **完成按钮**：status → done，若当前泳道不绑 done 则自动迁入该状态第一个泳道

### 3.3 数据与迁移（v4 → v5）
- `projects` 补 `swimlanes TEXT(JSON, 可空)`；`todos` 补 `swimlane_id TEXT`（幂等 ALTER）
- 存量 todo 按 status 回填 `swim-todo / swim-doing / swim-done`；存量项目 swimlanes 为 NULL → 前端 normalize 预置默认三泳道
- `save_state` 增加**泳道归属校验**（swimlaneId 必须属于项目泳道，否则按 status 回退）

### 3.4 涉及面
| 端 | 改动 |

| 前端 | types.ts（Swimlane、Todo.swimlaneId、Project.swimlanes）、normalize.ts（默认泳道/回填）、QuadrantBoard → **SwimlaneBoard**（布局+拖拽+泳道管理对话框）、详情页泳道 Select、TodoRow 行渲染 |

## 4. 验收标准

1. **默认形态**：新项目看板默认 3 列「待办/进行中/已完成」，待办按状态分布，每待办一行显示。
2. **拖拽落库**：跨泳道拖拽后，刷新/重开应用位置保持；`status` 与目标泳道绑定状态一致。
3. **泳道管理**：可新增（必选状态）/改名/排序/删除泳道；删除后其下待办迁移至同状态剩余第一个泳道，无数据丢失。
4. **详情页联动**：切换泳道 Select → 表单 status 同步；保存后看板位置正确；`?swimlane=` 预选生效。
5. **迁移**：v4 旧库打开即升级 v5（`user_version=5`）；旧待办全部出现在对应默认泳道；quadrant 旧值不影响显示与保存。
6. **回归**：完成自动补录、按时间窗补录、同步提交、切换分支、归档、主题皮肤、2s 外部同步均不回归。
7. **质量门禁**：`npm run build`、`cargo check`、`cargo clippy -- -D warnings`、`cargo fmt` 全绿；core 单测覆盖 v5 迁移与泳道校验。
8. **浏览器模式**：空态预览不报错（泳道用默认值渲染）。
9. **排序持久化**：泳道内拖拽排序后重开应用顺序保留（sortOrder 落库；同序按创建时间兜底）。
