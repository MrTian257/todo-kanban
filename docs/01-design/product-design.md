# 产品设计文档

> 来源：todo-git 产品设计（已按源码核实，基线 `40c0029` + 工作区）。

## 1. 产品定位

**Todo · Git**（重构代号 todo-kanban）是面向开发者的桌面待办管理应用：以「项目」为外层组织，待办绑定具体的代码目录与分支，并自动记录提交 hash，解决「上线时（尤其非正常上线需要 cherry-pick）找不到自己提交」的痛点。

- 形态：Tauri 2 桌面应用（窗口 1440×900，最小 1024×700）
- 语言：UI 文案与注释全中文
- 依赖：本机 `git` 在 PATH（所有 git 操作走系统 CLI）；可选系统 `curl`（GitLab 远端增强，Windows 10+ 自带）

## 2. 核心需求（演进史）

| 阶段 | 需求 |
| --- | --- |
| 基础 | 待办按「项目」组织；每条待办绑定代码库与分支（或新建分支）；记录提交 hash |
| 提交记录 | 记录待办**所有**提交 hash；支持按时间窗自动抓取与提交标记关联 |
| 看板化 | shadcn/ui + 四象限看板（可拖拽可排序）；项目层级侧栏；项目列表占位卡片 |
| 属性化 | 待办具备 startDate / endDate / blocker；完成态可归档（归档后不在活跃视图展示） |
| 主题 | 明暗 + 5 套皮肤（星尘/海洋/落日/森林/石墨）；切换按钮在侧栏左下角，设置页含皮肤选择 |
| 工程化 | 侧栏 shadcn sidebar；表单 RHF + zod；日期范围选择器；四象限 resizable（v4） |
| 补录与标记 | 完成按钮自动触发时间窗补录（从**创建待办起** ~ 完成）；可记忆提交标记 `todo-<序号>` |
| 分支体系 | 项目增加**生产分支名称**与**分支规则**（可视化配置分支流转流程） |
| 分支切出 | 新建分支必须指定**切出源**（默认生产分支），切出前自动 `git fetch` 拉取切出源最新内容；创建后自动推送远端**同名分支**并建立上游（不再指向切出源） |
| 分支查询 | 分支选择支持**搜索过滤**（BranchSelect，分支过多时快速定位） |
| 远端分支 | 项目可维护**前端/后端仓库地址 + GitLab Token**，分支下拉合并展示远端分支（内网自建 GitLab） |
| 待办详情页 | 新建/编辑待办改为独立页面：中间**所见即所得 Markdown 备注**（可直接粘贴图片入库）+ 右侧字段栏 |
| 泳道重构 | 看板由四象限**替换为泳道模式**：列=泳道（默认 待办/进行中/已完成，绑定状态）、行=待办；项目可自定义增删/改名泳道；跨泳道拖拽=改归属并落库 |
| AI 标记 | 任务/项目区分创建来源：经 MCP 创建的 todo/项目标记 **AI 创建**，经 MCP 修改的任务标记 **AI 协助**；任务卡片与项目卡片展示对应标记（人工创建为 human 不显示） |
| MCP 集成 | 设置页可**启用/禁用 MCP**（默认开启）并修改**授权 Token**（默认全局固定 `sk-GLOBAl_MCP_BY_ADMIN`）；MCP server 启动校验启用状态与 Token；AI 经 MCP 按代码目录登记拆分任务，目录无项目时自动新建（标记 AI 创建） |

## 3. 功能清单

### 3.1 项目（Project）

- 项目列表页 `/projects`：卡片展示（名称、生产分支、分支规则流程条、统计与状态）
- 新增/编辑/归档/删除项目；归档项目后待办全部保留（无恢复 UI，外部改库恢复，2s 轮询感知）
- 删除项目 = **级联删除**该项目全部待办
- 项目维护字段：名称*、项目目录、前端代码目录、后端代码目录、前端/后端仓库地址（http(s)）、**前端/后端仓库 GitLab Token**（前后端各自独立，明文存本地库）、**生产分支名称**、**分支规则**、**泳道配置 swimlanes**（默认三泳道「待办/进行中/已完成」，可增删/改名/排序，新增须绑定状态）
- **分支规则**（可视化）：一组有序步骤 `[来源角色] →(切出/合并) [目标角色]`；角色：生产/开发/测试/预发布/自定义；可暂停/启用；新建项目默认预置模板（生产→切出→开发；开发→合并→测试；开发→合并→生产）

### 3.2 待办（Todo）

- 字段：标题*、备注（Markdown，可含内嵌 base64 图片）、代码目录*（前端/后端/自定义）、分支*、**所属泳道 swimlaneId**、计划开始/截止日期（范围选择）、卡点 blocker、状态（待办/进行中/已完成）、全局序号 seq、提交标记 tag、提交记录 commits、开始/完成时间、归档标记（旧 quadrant 字段保留仅数据兼容，UI 不再使用）
- 生命周期：创建 →（开始）→ 进行中 →（完成）→ 已完成 →（归档）→ 归档；可重开（重开清空开始/完成时间）
- **新建/编辑入口**：独立待办详情页 `/project/:projectId/todo/:todoId`（`todoId=new` 为新建；看板/列表页点编辑或新建即跳转）
- 完成时**自动补录**：抓取「创建待办之后 ~ 完成时间」之间指定分支上的提交（committer date 过滤）；任意时刻可点「按时间窗补录」（恒从创建起、until 为最新时刻）
- 提交标记：`todo-<序号>`（全局递增，如 `todo-1`、`todo-12`），写入 commit message 如 `fix: xxx [todo-12]`，点「同步提交」自动检索关联
- 提交唯一性：一个 hash 只归属一个待办（时间窗/标记/手动三条路径全局去重）
- 切换分支：卡片/行上直接从仓库分支列表检出目标分支（成功后失效前后端分支缓存）
- 卡片还可：打开代码目录（系统文件管理器，tauri-plugin-opener）、复制提交标记、手动按短 hash 添加提交

### 3.3 泳道看板（Board，`/project/:projectId`）

- **布局：列 = 泳道，行 = 待办**；泳道绑定状态（todo/doing/done），**默认三列：待办 / 进行中 / 已完成**（按状态划分）
- **泳道管理（项目级）**：看板「管理泳道」入口——增删 / 改名 / 排序；新增泳道必须绑定一个状态（**一个状态可拆多个泳道**，如「已完成 → 已完成 / 已发布」）；删除泳道时其下待办归入同状态剩余第一个泳道
- **跨泳道拖拽** = 修改待办归属（swimlaneId + 状态联动）并落库；**泳道内拖拽排序**（dnd-kit，sortOrder 0..n 落库，重载保留）
- 已归档待办不展示；列头显示各泳道计数
- 新建待办默认归入「待办」泳道（详情页可改；支持 `?swimlane=` 预选）；完成按钮 → 状态 to done，若当前泳道已改绑其它状态则自动迁入「已完成」状态第一个泳道

### 3.4 其它页面

- `/focus` 今日焦点：进行中或今天创建、且项目未归档的待办
- `/todos` Todo List：全部待办一览（状态/项目筛选），支持快捷创建
- `/settings` 设置：明暗、主题皮肤（5 套）、侧边导航说明、数据说明
- 首路由 `/`：无项目时进 `/projects`（引导创建第一个项目），否则进 `/focus`

## 4. 关键交互流程

### 4.1 新建分支（从切出源）

1. 待办详情页勾选「新建分支」，输入新分支名
2. **切出源默认 = 项目生产分支**（可改选仓库其它分支，支持搜索）
3. 保存：后端先 `git fetch origin <切出源>` 拉取最新 → `git branch --no-track <新分支> origin/<切出源>` 切出（未配置远程/拉取失败回退基于本地切出源，文案注明）→ `git push -u origin <新分支>` 推送远端同名分支并建立上游（push 失败仅告警，不阻断保存）
4. 新建分支**不切换**当前工作分支；待办稍后可「切换分支」检出；成功后失效该仓库分支缓存

### 4.2 提交记录关联（两种方式）

- **方式一（时间窗，推荐）**：创建待办 → 在绑定分支提交 → 点完成自动补录（创建起 ~ 完成）；遗漏可随时「按时间窗补录」（恒从创建起 ~ 最新）
- **方式二（标记）**：提交 message 带 `[todo-<序号>]` → 「同步提交」检索全部分支
- **来源三分类标注**：两条路径均以任务分支为参考分支，对每条提交标注「原生（首次出现在该分支）/ 合并进来 / 剪切进来（cherry-pick）/ 不在分支上」，卡片提交列表以徽标 + tooltip 展示（合并的显示引入合并、剪切的显示来源）
- 上线时：正常上线直接合分支；非正常上线从待办提交记录复制 hash 做 `git cherry-pick`（cherry-pick 后新提交仍带原标记，再次同步也能查到）

### 4.3 远端分支增强（GitLab）

- 前提：项目维护了对应目录的「仓库地址（http(s)）+ Token」
- 分支下拉展示 = 本地分支 ∪ GitLab 远端分支（去重保序，分页拉取 ≤500）
- 三层缓存保证不打断操作：前端 60s 内存缓存 → 后端 SQLite 持久缓存（后台 30s 节流刷新）→ 定时预热（60s）；API 失败静默回退本地分支

### 4.4 泳道拖拽与泳道管理

1. 拖拽：PointerSensor（激活距离 6px）→ 泳道内重排 = `commitOrder`；**跨泳道 = `patchTodo({ swimlaneId, status })`**（status 取目标泳道绑定状态），均经 store action 落库（禁止只改本地状态）
2. 「管理泳道」对话框：新增（名称 + 绑定状态）/ 改名 / 拖拽排序 / 删除（该泳道下待办迁移至同状态剩余第一个泳道）；保存后 `projects.swimlanes` 落库
3. 新建项目默认预置三泳道；泳道缺失/悬空的旧数据由 normalize 按 status 回填（`swim-todo` / `swim-doing` / `swim-done`）

## 6. 非功能性约定

- UI 文案与代码注释全中文
- **git 依赖**：依赖本机 `git` 在 PATH 且版本 ≥ 2.20（启动时检测，不足中文提示、不阻塞）；一切 git 操作走系统 CLI，**统一注入隔离参数** `git -C <repo> --no-pager -c color.ui=false -c core.quotepath=false`（防用户全局 gitconfig 彩色输出/中文路径转义污染解析）；可选系统 `curl`（GitLab 远端增强）。远期备选：gitoxide（纯 Rust）消除外部依赖（仅 ADR 备注，不落地）
- **错误处理分级**：命令内不 panic；业务错误 → 中文 toast（可操作提示）；系统错误（git/curl 失败）→ 中文 toast + 完整上下文（命令、repo、stderr）落 tauri-plugin-log；**外部子进程统一超时：git 30s / curl 10s**（防网络挂起卡死写操作）
- **数据安全**：SQLite 单文件自动备份——启动时 / 每日首次写前复制 `todo-git.db` → `todo-git.db.bak`（WAL + 差异写下成本可忽略）；数据库打开失败时**先备份坏库**（追加时间戳）再回退空态，toast 提示文件路径
- **浏览器预览模式**：`npm run dev` 无 git 能力、**无本地存储**；渲染**内置演示数据种子**（只读、可一键重置、顶部横幅标注「预览模式」）便于 UI 联调；完整功能仅桌面端；**不恢复** localStorage 双通道（历史包袱 `todo-git.app.v2`）
- **性能基线**：冷启动（数据加载）< 1.5s；单项目千级待办泳道看板滚动流畅（React 19 memo，必要时虚拟滚动）；2s 外部同步轮询开销趋近零（后端指纹缓存）
