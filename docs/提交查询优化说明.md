# Git 集成说明

本文说明 Todo Kanban 使用的 Git 信息与远端提交平台。平台实现和边界以 `src-tauri/core/src/svc/` 为准；当前代码包含本地 Git CLI、GitLab 与 GitHub provider。

## 本地仓库操作

待办可以关联代码目录和分支。应用通过系统 Git CLI读取分支/提交信息并执行部分分支操作。Git 不可用、路径不存在或工作区状态不符合要求时，相关功能可能返回错误；应用启动时会检测 Git CLI。

## 远端平台

`forge.rs` 根据仓库地址识别 GitHub 或 GitLab，并将各平台响应映射为统一提交模型。支持 GitLab、自建 GitLab、GitHub 及常见 GitHub Enterprise 域名；不明确的域名按实现规则识别或探测。认证凭据来自项目仓库配置。

远端 API 查询与本地 Git 查询的数据范围不同：API 通常只返回服务端可见提交；本地回退只能反映本地已有 refs。是否回退、分页和平台接口限制应以 `forge.rs`、`gitlab.rs`、`github.rs` 对应调用为准。

## 提交关联与报告

待办可关联匹配到的提交；可按标记或时间范围同步，亦可查询单个 hash。项目报告在日报、周报、月报等周期内汇总 Git 提交。报告查询是独立读取流程，开发人员归类等报告配置由应用状态保存。

## 分支行为

新建分支、从指定分支创建和检出分支由 Git service 执行。检出分支会改变仓库工作区，属于有副作用的操作。MCP 客户端需遵守工具的破坏性标记并按自身交互规则取得确认。

## 故障排查

1. 确认项目代码目录存在且是 Git 仓库。
2. 确认本机 Git CLI 可用。
3. 检查仓库 URL 与访问 Token，特别是私有仓库权限。
4. 区分 API 查询结果和本地回退结果的可见范围。
5. 查看应用日志或 MCP 审计记录；不要把 Token 写入共享日志。

此前文档中的 API 时限、页数、测试结果和构建体积均属于特定历史版本数据，不作为当前承诺；如需精确运行限制，请直接核对 provider 实现和配置常量。
