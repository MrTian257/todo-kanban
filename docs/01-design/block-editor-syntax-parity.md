# Markdown 编辑语法范围

当前块编辑器以 Markdown 字符串为存储格式，通过 remark/micromark 生态进行解析，Lexical 负责交互编辑。编辑期和只读呈现使用 `src/lib/markdownPlugins.ts` 中共享配置。实现变化时，核对解析、块文档桥、编辑节点和只读渲染是否保持一致。

## 主要块类型

当前数据桥和 Lexical 节点覆盖的常用结构包括：段落、标题、列表（含任务列表）、引用、GFM 表格、代码块、分隔线、图片、链接以及项目支持的数学/源文节点。未识别或不适合结构化编辑的内容由源文节点承接。具体支持细节以 `markdownBlocks.ts` 和 `blockDocument.ts` 的类型/分支为准，新增语法应补充对应逻辑断言。

行内结构包括强调、粗体、删除线、行内代码、链接和换行等。附件引用与展示 URL 由附件模块负责转换。

## 保真原则

- 未修改块优先沿用原始 Markdown 源文，避免全篇格式化。
- 修改后的块由编辑器文档桥序列化；其标记、空行及行尾空格保真能力需要以当前逻辑检查覆盖为准。
- 块节点和编辑器内部 ID 不属于持久化模型。
- 不能确认支持的 Markdown 扩展，不应在文档中宣称可结构化编辑；应保留源文或明确降级行为。

## 变更要求

每次添加或修改语法，至少核对：

1. 输入 Markdown 能否被解析并呈现为正确节点。
2. 不编辑时是否保留原始源文。
3. 修改后是否得到预期 Markdown。
4. 只读渲染是否正确显示同一语法。
5. 资料和待办两种附件 owner 是否分别正确。

纯逻辑覆盖位于 `scripts/test-markdown-blocks.mjs`、`test-block-document.mjs`、`test-markdown-plugins.mjs` 等脚本中。运行这些脚本需遵循仓库测试约定。
