# ADR-009：泳道看板替换四象限（状态为唯一事实源）

## 状态
Accepted（v2.0.0 已实施，提交 a31e4de；PRD 见 docs/01-design/prd-swimlane.md）

## 日期
2026-09-03

## 背景
原设计为艾森豪威尔四象限（do / schedule / delegate / eliminate）。实际使用中开发者更关心待办所处**阶段**（待办 / 进行中 / 已完成）而非优先级矩阵；且四象限与 status（todo/doing/done）两套维度并存、语义重叠，拖拽落库需同时维护两个真相。

## 决策
看板替换为泳道模式——**列 = 泳道、行 = 待办**：
- 默认三泳道绑定 todo / doing / done；项目级自定义增删 / 改名 / 排序；新增泳道必须绑定一个状态，**每个状态至少保留一个泳道**（删除拦截）
- **状态是唯一事实源**：泳道只是状态的分组容器，一个状态可拆多泳道（如「已完成 / 已发布」都绑 done）
- 跨泳道拖拽 = 修改归属并落库：swimlaneId + status 联动（同状态跨泳道仅改 swimlaneId，status 不变）
- quadrant 字段保留仅数据兼容，UI 不再展示 / 编辑（不做字段清理）
- schema v4→v5：projects.swimlanes（JSON 列）+ todos.swimlane_id；存量按 status 无损迁移回填默认泳道

## 备选方案

### 保留四象限 + 并排泳道视图
- 否决：双视图双真相，数据模型需同时维护两套维度，拖拽语义复杂化

### 多维泳道（如人员 × 状态）
- 否决：单机单用户场景无协作维度需求（PRD 明确非目标）

### 直接删除 quadrant 字段
- 否决：旧库 / 旧数据兼容风险；保留仅数据兼容，后续可单独清理（PRD 风险 #5）

## 后果
- 拖拽语义简化为「改归属」：泳道 + 状态一个动作一个真相，避免双真相漂移
- 删除泳道时其下待办自动迁入同状态剩余第一个泳道；save_state 泳道归属校验 + 前端 normalize 回退双兜底
- 详情页象限按钮替换为泳道 Select（按状态分组，切换联动 status）；完成按钮自动迁入绑 done 的第一个泳道
- quadrant 冗余列为已知技术债（有意保留，非必须清理）
