# ADR-006：任务全局序号与提交唯一归属（app_meta.next_seq + 全局去重）

## 状态
Accepted（重构基线）

## 日期
2026-09-03（todo-git 基线核实）

## 背景
提交标记 tag = todo-<n> 需全局唯一（跨项目，供手写进 commit message 做关联锚点）；存在多窗口并发保存；提交关联有三条路径（时间窗补录 / 标记同步 / 手动添加），同一 commit hash 可能被重复抓取。历史问题：并发保存导致序号冲突、同一提交归属多个待办。

## 决策
- 序号源：SQLite app_meta 表 key=next_seq（已分配最大序号）；save_state 在写锁内取号收敛——冲突 / 无序号待办重分配全局唯一 seq 并同步改写 tag；前端 max+1 仅为预生成
- 提交唯一归属：save_state 写锁内全局去重（库中既有优先、本批先到先得）；前端运行时 dedupeCommitsForTodo 合并前剔除已被其它待办占用的 hash；normalize 后 dedupeTodosCommits 修正历史脏数据
- v1→v2 迁移：存量数字标记全局去重 + seq 对齐，最大序号写入 next_seq（幂等可重复执行）

## 备选方案

### 前端 max+1 即最终值
- 否决：多窗口并发必冲突（两窗口同时算出同一序号）

### UUID 作标记
- 否决：不可人类阅读 / 手写，无法作为 commit message 中的关联锚点

### 允许一个提交多归属
- 否决：上线检索（cherry-pick 场景）会重复计数，破坏提交记录可信度

## 后果
- 保存时序号可能被后端改写（tag 随之变化）——前端不得假设预生成序号稳定
- 补录「已被其它待办占有」的提交会被静默剔除（有意取舍：唯一归属优先）
