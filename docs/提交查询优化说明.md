# 提交查询与可选分支

## 已实现

- 按标记同步、时间窗补录、单条 hash 查询统一在 core 选择数据源，桌面与 MCP 复用。
- 通过代码目录匹配项目的前端/后端仓库 URL 和 Token，优先调用 GitLab Commits API。配置冲突不猜测；未配置、请求失败或分页不完整时回退本地 Git，并记录日志。API 成功返回空列表时不回退。
- API 每页 100 条，逐页读取、按 hash 去重；超过 100 页或总耗时保护则报错回退，不返回部分结果。单页请求仍受 10 秒超时约束。
- 标记匹配完整 message 并校验边界，todo-1 不匹配 todo-12。时间窗映射 since/until，提交日期使用 committed_date。
- 新建/编辑任务不再要求分支；新任务默认空分支，已有分支可清空。手动补录和 MCP 时间窗调用支持空分支；完成时未指定分支则不自动补录。
- 无分支时 API 使用 all=true，本地使用 git log --all；指定分支时只查询该分支时间窗。创建/切换分支的参数校验保持有效。

## 使用与边界

项目中配置 GitLab 仓库 HTTP(S) 地址，并为私有仓库配置可读取仓库的 Token。现阶段未实现 GitHub 或其他托管平台适配。

API 结果表示服务端已有提交，不包含尚未推送的本地提交；API 失败后的本地结果只反映本地已有 refs，未额外 fetch。API 路径不再逐条调用 Git 补充分支归属或扫描来源，branches/origin/mergeHash/source 保持空值；本地回退保留原来的补全行为。

GitLab 接口依据：https://docs.gitlab.com/api/commits/

## 后续优化

以下建议已继续实施，当前设计与未验证范围见《后端与前端优化说明.md》。原建议：

1. 提交查询增加增量缓存、同条件请求合并，以及 UI 数据源/回退原因提示。
2. 本地提交来源分析按需执行并缓存，减少逐提交 branch --contains 和跨分支 git cherry 子进程。
3. 配置查询改为仅读取项目字段，避免每次提交查询加载完整待办状态；外部同步同样可改用可靠修订号增量读取。
4. curl 默认系统 TLS 验证与系统钥匙串存储 Token，不增加内网 CA 定制。
5. 泳道数据先单次分组再排序，避免每条泳道重复过滤完整待办列表。
6. Markdown 渲染包按使用场景进一步拆分，并减少不需要的字体资源；本次构建该 JS 分块约 786 KB（gzip 237 KB）。

## 验证范围

新增 Rust 测试覆盖全分支查询、指定分支过滤、标记边界、API 分页去重、分页失败/上限、配置匹配和冲突。真实 GitLab 联调和桌面交互验收未执行。

验证结果：前端 npm run build 通过；Rust core 57 项和 MCP 10 项测试全部通过；cargo clippy --workspace -- -D warnings 通过；git diff --check 通过。

## 主动刷新（后续代码改动，未测试）

- 项目看板增加“刷新提交”：刷新当前项目全部未归档待办，不受看板筛选影响。
- 全部待办增加“刷新当前结果”：仅刷新当前筛选结果，包括选择归档筛选时显示的待办。
- 原有单条待办同步入口也复用刷新流程。每次重新请求，不使用提交缓存；最多 3 个并发请求，全局互斥防止重复刷新。
- 展示刷新进度、成功待办数、新增提交数、跳过数及失败信息。刷新前保存配置，刷新后等待持久化完成。
- 使用当前状态合并提交并去重；请求期间任务有改动则跳过，保留已有提交。浏览器预览禁用刷新入口。
- 按用户后续要求，本节及相关代码修改未运行测试、构建或验证命令。上面的通过结果仅适用于添加主动刷新之前的版本。

## 完成规则调整（未测试）

完成待办时，仅在代码目录和分支均非空时自动补录；未指定分支（包括空白字符串）时不请求提交接口、不新增提交，保留已有提交，并正常写入完成时间。主动刷新和手动补录继续允许不指定分支。
