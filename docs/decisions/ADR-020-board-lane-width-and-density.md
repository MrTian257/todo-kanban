# ADR-020：看板列宽改容器基准 + 紧凑行视图

## 状态

Accepted（2026-10-14 已实施）

## 日期

2026-10-14

## 背景

真实数据里存在 8 泳道的项目（`projects.swimlanes` 项目级自定义，泳道数无上限）。实测（CDP + 生产构建，1440×900）：

- 撑满档 `--tk-lane-min: 20vw` 按**视口**宽度算，未扣侧栏（224px）与页面内边距，代码注释承诺「一屏最多并排 5 条」，实测只能完整看到 **3 条**，第 4 条被切一半；
- 卡片实测高 175–258px，正文文字仅 38 字符，一屏每列可见 **2 条**任务 → 8 泳道项目一屏约看到 6 条 / 共 29 条；
- 横向溢出 1241px，但滚动条在容器最底部、`scroll-snap: none`、无边缘提示，用户不知道后面还有泳道。

## 决策

1. **列宽以滚动容器为基准**：`--tk-lane-min: clamp(200px, calc((100% - 80px) / 5), 320px)`、`--tk-lane-max: calc((100% - 40px) / 3)`。
   百分比在 flex 项上解析到**容器内容盒**，天然扣掉侧栏与内边距，与注释里的「并排 5 条」重新一致；200px 下限保证窄窗口宁可横向滚动也不挤成不可读。
   仅改撑满档；小 / 大档保留显式像素值（那是用户主动选的密度）。
2. **溢出必须可见**：右缘渐隐遮罩 + 「还有 N 条泳道 →」浮动按钮（点一次翻 0.8 屏），滚到中间后左侧补「← 前面的泳道」。按钮在拖拽期间隐藏，避免吃掉落点。
   计数由 `ResizeObserver` + `onScroll` 测量，状态变化才 `setState`（引用比较），不引入轮询。
3. **卡片密度是视图偏好，不是数据**：看板头部新增切换按钮，`data-card-density="compact"` 挂在看板容器上，纯 CSS 重排（标题一行、其余字段同行流式），**不隐藏任何字段**，备注与提交仍走展开。
   存 `localStorage["tk-board-card-density"]`（原值 `compact` / `card`，与 `tk-sidebar-collapsed` 同风格），**不进 SQLite、不进 MCP 快照、不动数据版本**。

## 备选方案

### 泳道数超过可见列时自动等分压缩列宽
- 否决：8 列等分到 140px 时标题与徽标全部换行，比横向滚动更难读；用户明确要「看全流程」时才需要多列同屏。

### 紧凑模式做成全局「展示尺寸」第四档
- 否决：展示尺寸是全局排版密度（含表单、设置页），而卡片密度只在看板有意义，两者绑定会让设置页跟着变紧凑。

### 紧凑模式隐藏分支与自定义字段以省高度
- 否决：分支是本项目找回提交的核心线索，隐藏后用户会以为数据丢了。

## 后果

| 视口 / 模式 | 完整可见泳道 | 每列可见任务 | 一屏可见任务 |
| --- | --- | --- | --- |
| 1440×900 卡片（改前） | 3 | 2 | 6 |
| 1440×900 卡片（改后） | 5 | 2 | 10 |
| 1440×900 紧凑 | 5 | 4 | 20 |
| 1147×690 卡片（改前） | 3 | 1 | 3 |
| 1147×690 紧凑（改后） | 4 | 3 | 12 |

- 列宽变化会影响拖拽落点几何，`scripts/verify-dnd.mjs` 六个场景必须随改动回归（已通过）。
- 密度偏好是**每台设备**的，多设备/多窗口不同步，属有意取舍。
- 浮动按钮会遮住最右列约 120×28px 区域，换取「还有更多列」的可发现性。
