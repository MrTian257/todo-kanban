# 块编辑器语法子集对齐表（票 07 产出）

> 口径来源：ADR-0001 §5（12 类封闭块集）+ 票 02 的直通名单 + ADR-0003 决策 3（**编辑期与只读侧共用同一套 remark 插件配置**）。
> 本表是「不许出现编辑能造、只读显示不出」的**唯一权威清单**；实施与验收都以它为准，新增块类型必须先改本表。

## 1. 一致性由构造保证，不靠人工核对

ADR-0003 签的是**共用 remark 栈**，因此落一个单一来源模块：

```ts
// src/lib/markdownPlugins.ts —— 编辑期块解析与只读渲染共用同一份插件清单。
// 分叉过一次就会出现「编辑器能造、看板显示不出」，所以这里必须是唯一的一份。
export const remarkPlugins = [remarkGfm, remarkMath];   // 与只读侧同版本
export const rehypePlugins = [rehypeRaw, [rehypeSanitize, schema]];
```

- 只读侧 `src/components/todo/MarkdownRenderer.tsx` 现在自带 `remarkPlugins=[remarkGfm]` + `rehypePlugins=[rehypeRaw, rehypeSanitize]`，并按内容懒加载 `MarkdownMath.ts` / `MarkdownCode.ts`（`MarkdownView.tsx` 用 `$` 与代码围栏探测选 4 个渲染器之一）。**改造方向是把这份配置抽到 `markdownPlugins.ts` 让两侧都 import**，不是把只读侧改成块编辑器。
- 脚注与数学按 ADR-0003 决策 5 **自接扩展**（`remark-math` 与 footnote 通道），与只读侧 `remark-gfm` / `rehype-katex` 同源同版本；`katex` 现锁 0.16.47 保持不变。
- **注意重复注册**：`remark-gfm@4` 已内置 footnote，**不要**再单叠一份 `micromark-extension-gfm-footnote`（两处注册会双写 handler）。只有当某侧不走 gfm 的 footnote 通道时才需要单列。这条是本表里最容易做错的一处，实施票要显式核对。

## 2. 12 类块 × 编辑期 × 只读侧 × 断言

| # | 块类型 | 源文形态 | 编辑期行为 | 只读侧（现状即达标） | 断言落点 |
| --- | --- | --- | --- | --- | --- |
| 1 | 段落 | 裸文本 | 可行内编辑；`Shift+Enter` 写行尾两空格硬换行 | react-markdown 段落 | 逐字往返（未碰块） |
| 2 | 标题 | ATX 一至六级 | Setext 读入为同级标题，**被碰过才**回写成 ATX | ✅ | Setext→ATX 仅在被碰时；未碰原样 |
| 3 | 列表 | 无序 / 有序（含非 1 起始 `start`）/ 任务项 | **整棵列表树 = 一个块**；层级只靠 `Tab` / `Shift+Tab` | ✅（含嵌套、任务态） | 非 1 起始序号保真；整树不可分隔 |
| 4 | 引用 | 单层与嵌套 | 嵌套引用算同一块 | ✅ | 嵌套层级逐字 |
| 5 | 表格 | GFM 管道表（对齐、转义竖线） | 整表一个块；单元格可编辑但**不可拖** | ✅（`.md-table-scroll` 容器内横滚） | 对齐标记与转义竖线保真 |
| 6 | 围栏代码 | 三反引号或波浪号，含未知语言 | 被碰过时按内部内容加长外层围栏 | ✅（`rehype-highlight`，未知语言仍显示） | 内部三反引号不被提前闭合 |
| 7 | 缩进代码 | 4 空格 / Tab | 显示为代码块；未碰原样，**碰过归一为围栏**（唯一允许的形态转换） | ✅（CommonMark 本就支持） | 归一转换有断言；**实测存量 0 条 ⇒ 低优先级** |
| 8 | 块级公式 | 双美元号包裹 | 编辑期显示源文 + 只读预览（MathML，不引数学字体） | ✅（`MarkdownMath.ts` + `rehype-katex`） | 块公式不被当代码吞 |
| 9 | 分隔线 | 三横线 / 三星号 | 可造可删 | ✅ | 不误判为 Setext 下划线 |
| 10 | 图片块 | 独立成段的图片语法 | 附件 / 远程 / 历史 data URL 三类同源 | ✅（`safeUrl` 放行 attachment 协议与栅格 data URL） | 引用形态 ↔ 展示形态可逆 |
| 11 | 链接定义 / 脚注定义 | 定义型链接与脚注 | 各为一块，**固定文档尾部、不参与拖拽重排** | ✅（脚注回链靠 `scrollIntoView`，不改 `location.hash`） | 定义与正文引用同时保真 |
| 12 | 透明块 | 任意无法识别区间 | **不可拆**：只给「编辑源文 / 上移 / 下移 / 删除」四项，逐字节回写 | ✅（原样透传，不宣称渲染） | 「全收集、不丢弃」+ 逐字节恒等 |

**明确不做**（ADR-0001 §2/§5）：分栏、toggle 折叠、callout、同步块 / 块引用 / 块锚点 / 块级评论、块图标、文字颜色 / 背景 / 块宽、把待办本身当块。跨对象关系继续走已有的「关联资料 / 依赖 / 子任务」。

## 3. 直通名单：真实语料里「不是块」的源文（实测自 `release/todo-kanban.db` 只读采样）

这些一律落 **§2 第 12 类透明块**，逐字进出、不规范化、不报错：

| 形态 | 实测条数 | 编辑期呈现 | 为什么不能做成块 |
| --- | --- | --- | --- |
| 中文手写序号「1、」「2）」 | 待办 11 / 资料 1 | 段落（透明块） | CommonMark 不认，做成列表会**把正文当列表拆散** |
| 以短横线开头接中文的伪列表 | 待办 8 | 段落（透明块） | 同上，这是票 02 否掉「按列表项拆块」的实测依据 |
| 反斜杠转义（含伪标签如 `<service\_case\_id>`） | 待办 9 | 段落（透明块） | 转义符一旦被序列化吃掉，字面量就变了 |
| 任意原始 HTML 标签（含 2 条 br 连排） | 待办 7 | 透明块；只读侧仍走 `rehype-sanitize` | script / iframe / javascript: / SVG data URL **不得执行或导航**（测试计划 MD-14） |
| 裸 URL（依赖 linkify 语义） | 待办 9 / 资料 3 | 段落内联 | 自动链接是渲染期行为，源文里没有链接语法 |
| 行尾空格（真硬换行 ≥2 空格 22 行、恰好 1 空格 23 行，共 45 行 / 6 条） | 待办 3 / 资料 1 | 原样保留，**互不转换** | ADR-0001 §6「不做形式统一」的实测依据 |
| 软换行（段内单换行） | **46/83 条待办正文含紧邻换行** | 原样保留 | 软换行是本仓库的**主要排版手段**，统一转换会让用户在自己碰过的那段里看到没要求的断行 |
| 真 Setext 标题 / 围栏代码 / 缩进代码 / 脚注 / 历史 base64 图片 / Mermaid·MDX·容器·HTML 注释 / 任务模板 note | **各 0 条** | —— | 存量为零 ≠ 不支持；仍按 §2 与透明块规则处理，**不强制迁移** |

> **口径对账**：票 03 记「私有方言 0 条」测的是 Mermaid / MDX / 三冒号容器 / HTML **注释**；票 02 记「原始 HTML 7 条」测的是任意 HTML **标签**（如 br）。两条不矛盾，是两套检测规则，本表两行分别记录——**后续会话不要把它当数据冲突"修正"掉**。

## 4. 非块写入者侧（ADR-0001 §8）

| 写入者 | 是否渲染正文 | 结论 |
| --- | --- | --- |
| 局域网访客面板 `src-tauri/src/lan_guest.html` | **不渲染**——实测 `note` 只出现在编辑弹窗的 textarea（`:441`）与提交载荷（`:489` / `:519` / `:538`），`renderCard` 不显示备注 | 因此**不存在"访客侧降级显示"问题**；访客写回的整串 Markdown 由桌面端块编辑器负责解析。票 07 原担心的这一格实测为空 |
| MCP `db_save_state`（AI 写整串） | 不渲染 | AI **不需要知道块的存在**：它写 Markdown，块是视图。这条是 ADR-0001 §1 的核心红利 |
| 自动脚本 `automation_backfill` | 不渲染正文（写自定义字段） | 不涉及 |
| 看板卡片 `TodoRow.tsx` / 资料详情弹窗 `ResourceDetailDialog.tsx` | 渲染（`MarkdownView`） | 与编辑期共用 §1 的插件配置 ⇒ 由构造一致 |

**不承诺跨写者的尾随空格保真**：访客 textarea 或 AI 整串写入若吃掉行尾空格，属外部写者的规范化，块编辑器不负责、也**不因此回写库**（ADR-0001 §6）。

## 5. sanitize 与安全边界

- `rehype-sanitize` 的 `defaultSchema` + 现有两处放宽（`code.className` 允许 `language-*` / `math-inline` / `math-display`；`protocols.src` 追加 `data` / `attachment`）**保持不变**——块编辑器不产出这之外的新面，所以**不需要扩 schema**。
- `safeUrl` 只放行附件协议（换展示 URL）与 png/jpeg/gif/webp 的 data URL，其余走 `defaultUrlTransform`。块编辑器的图片块必须走同一函数，**不得自己拼 URL**（否则 Windows 与 macOS 的协议形态会分叉）。
- 编辑期内链接点击一律 `preventDefault`（现行 `guardEditorClick` 行为），脚注锚点用 `scrollIntoView` 不改路由。

## 6. 本票签完后的状态

- 「编辑能造、只读显示不出」由 §1 的单一插件来源 + §2 的 12 行 + §3 的透明块规则三重封住。
- 遗留到验收的可测项全部并入票 06 的断言清单（`docs/01-design/block-editor-acceptance.md`），本表每行的「断言落点」列就是它的索引。
- **不改动只读侧的渲染实现**，只把插件清单抽成共用模块；`MarkdownView` 的 4 路懒加载渲染器与「（无备注）」空态保持不变。
