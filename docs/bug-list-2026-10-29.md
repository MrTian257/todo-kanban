## P1（未修复）

### BUG-001 默认 MCP 授权 Token 是公开常量，且默认开启

- 位置：`src-tauri/core/src/models.rs:367,380-387`
- 状态：已确认
- 现象：`DEFAULT_MCP_TOKEN = "sk-GLOBAl_MCP_BY_ADMIN"` 写在源码里，`McpSettings::default()` 直接用它且 `enabled: true`。MCP HTTP 一旦启用（默认 Token 未改），任何能访问端口的本地进程/网页都能凭公开值获得完整读写权限。
- 放大条件：Origin 校验只要求 `Origin == Host`（防 DNS 重绑定的 Host 白名单在 `1734e50` 引入过，但会误杀主机名访问，本轮已放宽）；攻击者可让 `evil.com` 解析到 `127.0.0.1`，以同源 Origin 调 `/mcp`。
- 建议：首次启用 MCP 时强制生成随机 Token / 提示更换；HTTP 仅绑定 loopback 时对已知默认值拒绝；文档明确“默认值仅供本机调试”。

### BUG-002 提交来源标注在常见仓库规模下整体失效且不缓存

- 位置：`core/src/svc/git_cmds.rs:617-647`（`detect_cherry_picks`）、`:609`（`?` 传播）、`:548-551`（`None` 直接 return）
- 状态：已确认
- 现象：本地+远端分支合计 >16 条，或任一 `git log`/`git cherry` 超过 1s 预算，`detect_cherry_picks` 返回 `None` → `build_origin_analysis` 整体失败 → native/merge/cherry 标注全部为空；失败结果不写缓存，每次提交列表请求重付最多 5s。
- 影响：普通多分支仓库的 Git 报告“提交来源/合并来源”整块静默缺失；旧实现至少能给出 native/merge/other。
- 建议：cherry 探测降级为可选增强（失败返回空集合而非 `None`），超分支只跳过补丁等价、保留尾注；失败写短 TTL 的 degraded 缓存。
