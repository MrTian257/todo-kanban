## 1. 引言

### 1.1 编写目的

为 todo-kanban 重构开发提供唯一的、自包含的软件设计基线：统一描述产品需求、系统架构、数据模型、接口契约、前后端设计、核心流程与关键决策，供重构实施、评审与新人上手使用。

### 1.2 项目背景

todo-kanban 是原项目 **todo-git**（`C:\workspace\desktop\todo-git`）的重构工程。设计基线整理自 todo-git（commit `40c0029`），并在本仓库演进：**v2.0.0 已按基线全量实现**（React 19 + TypeScript + Vite 7 前端，Rust workspace 后端，MCP server），随后以泳道看板替换四象限（PRD 见 docs/01-design/prd-swimlane.md，schema 升至 v6）。

### 1.3 术语

| 术语 | 含义 |
| --- | --- |
| 泳道看板 | 看板列 = 泳道（默认 待办/进行中/已完成），行 = 待办；项目可自定义增删泳道（**替换原四象限**） |
| 泳道（Swimlane） | 看板的一列，绑定一个状态（todo/doing/done）；一个状态可有多个泳道；项目级配置存于 projects.swimlanes |
| 四象限 | 原艾森豪威尔矩阵（do/schedule/delegate/eliminate）——**已被泳道看板替换弃用**，quadrant 字段仅保留数据兼容 |
| 提交标记 tag | `todo-<全局序号>`，写入 commit message 用于自动关联，如 `fix: xxx [todo-12]` |
| 分支规则 | 项目级分支流转流程：一组有序步骤 `[来源角色] →(切出/合并) [目标角色]` |
| 数据源指示文件 | 程序运行目录下 `db-config.txt`，首行 = SQLite 数据库绝对路径 |
| MCP | Model Context Protocol；`src-tauri/mcp-server` 以 stdio 对外暴露核心能力 |
| Db* | Rust 侧落库模型（models.rs），与前端 types.ts camelCase 强对齐 |

## 2. 产品概述

### 2.1 产品定位

面向开发者的桌面待办管理应用（Tauri 2，窗口目标 1440×900 / 最小 1024×700）：以「项目」为外层组织待办，每条待办绑定代码目录与分支并**自动记录提交 hash**，解决「上线（尤其非正常上线需 cherry-pick）时找不到自己提交」的痛点。UI 文案与代码注释全中文。

### 2.2 功能清单（目标设计）

**项目（Project）**
- 项目列表 `/projects`：卡片展示（名称、生产分支、分支规则流程条、统计与状态）；新增/编辑/归档/删除
- 删除项目 = 级联删除全部待办；归档项目待办保留（无恢复 UI，外部改库恢复，2s 轮询自动感知）
- 字段：名称*、项目目录、前端/后端代码目录、前端/后端仓库地址（http(s)）、**前端/后端 GitLab Token**（各自独立、明文存本地库）、生产分支名、分支规则（可视化编辑器：有序步骤、角色=生产/开发/测试/预发布/自定义、动作=切出/合并，可暂停/启用，新建项目预置模板）、**泳道配置 swimlanes**（默认三泳道「待办/进行中/已完成」，可增删/改名/排序，新增须绑定状态）

**待办（Todo）**
- 字段：标题*、Markdown 备注（可含内嵌 base64 图片）、代码目录*（前端/后端/自定义）、分支*、**所属泳道 swimlaneId**、计划起止日期、卡点、状态(todo/doing/done)、全局序号 seq、提交标记 tag、提交记录 commits、开始/完成时间、归档标记（旧 quadrant 字段保留仅数据兼容，UI 不再使用）
- 生命周期：创建 →(开始)→ 进行中 →(完成)→ 已完成 →(归档)→ 归档；可重开（清空开始/完成时间）
- 新建/编辑走**独立待办详情页** `/project/:projectId/todo/:todoId`（`todoId=new` 为新建）
- 提交关联双通道：① 时间窗（推荐）——完成时自动抓取「创建 ~ 完成」区间绑定分支提交，可随时「按时间窗补录」（恒从创建起、until 为最新）；② 标记——commit message 带 `[todo-<序号>]`，「同步提交」全分支检索
- 提交唯一性：一个 hash 只归属一个待办（时间窗/标记/手动三条路径全局去重）
- 行/卡片操作：开始/完成(自动补录)/重开、归档、切换分支、打开代码目录（plugin-opener）、同步提交、补录、手动按短 hash 加提交、复制标记、编辑、删除

**泳道看板** `/project/:projectId`
- **列 = 泳道，行 = 待办**：每个待办占一行，落在所属泳道列；默认三列「待办(todo) / 进行中(doing) / 已完成(done)」，按状态划分
- **项目级自定义泳道**：增删 / 改名 / 排序；新增泳道必须绑定一个状态（一个状态可有多个泳道，如「已完成 → 已完成 / 已发布」）；删除泳道时其下待办归入同状态剩余第一个泳道
- 拖拽（dnd-kit）：**跨泳道拖拽 = 修改待办归属并落库**（泳道绑定状态 → 同步更新 status）；泳道内拖拽排序
- 泳道内排序持久化（todos.sortOrder，v6）：拖拽后 0..n 分配落库，重载按 sortOrder 还原（同序按 createdAt 兜底）
- 归档待办不展示；泳道列头显示计数

**其它页面**
- `/focus` 今日焦点（进行中或今天创建、项目未归档）；`/todos` Todo List（状态/项目筛选、快捷创建）；`/settings` 设置（明暗、皮肤、数据说明）；`/` 按有无项目重定向

**主题**：明暗(light/dark/system，next-themes) × 5 套皮肤（星尘 default / 海洋 ocean / 落日 sunset / 森林 forest / 石墨 graphite），`<html data-theme>` + CSS 变量覆盖，localStorage `todo-git.skin.v1` 持久化。

### 2.3 非功能约定

- **git 依赖**：依赖本机 `git` 在 PATH 且版本 ≥ 2.20（启动时检测，不足中文提示、不阻塞）；一切 git 操作走系统 CLI，**统一注入隔离参数** `git -C <repo> --no-pager -c color.ui=false -c core.quotepath=false`（防用户全局 gitconfig 彩色输出/中文路径转义污染 `%x1f` 解析）；可选系统 `curl`（GitLab 远端增强）。远期备选：gitoxide（纯 Rust）消除外部依赖（仅 ADR 备注，不落地）
- **错误处理分级**：命令内不 panic；业务错误 → 中文 toast（可操作提示）；系统错误（git/curl 失败）→ 中文 toast + 完整上下文（命令、repo、stderr）落 tauri-plugin-log；**外部子进程统一超时：git 30s / curl 10s**（防网络挂起卡死写操作）
- **数据安全**：SQLite 单文件自动备份——启动时 / 每日首次写前复制 `todo-git.db` → `todo-git.db.bak`（WAL + 差异写下成本可忽略）；数据库打开失败时**先备份坏库**（追加时间戳）再回退空态，toast 提示文件路径
- **浏览器预览模式**：`npm run dev` 无 git 能力、**无本地存储**；渲染**内置演示数据种子**（只读、可一键重置、顶部横幅标注「预览模式」）便于 UI 联调；完整功能仅桌面端；**不恢复** localStorage 双通道（历史包袱 `todo-git.app.v2`）
- **性能基线**：冷启动（数据加载）< 1.5s；单项目千级待办泳道看板滚动流畅（React 19 memo，必要时虚拟滚动）；2s 外部同步轮询开销趋近零（后端指纹缓存）

## 4. 数据设计

### 4.1 模型对齐原则（硬约束）

- 前端 `src/lib/types.ts` ↔ Rust `core/src/models.rs` 的 Db*：**camelCase 字段一一对应**（serde rename_all=camelCase）；改/加字段必须两端同步（必要时同步 DDL / row 映射 / normalize）
- **唯一例外**：`GitInfo` 为 snake_case（repo_exists / is_repo / current_branch / branches / error）
- SQLite 列名 snake_case，由 db/row.rs 双向映射；**列序是硬契约**（schema ↔ row ↔ mod 的 SELECT/INSERT 三处同步）

### 4.2 核心实体

**Todo（DbTodo，todos 表 21 列）**：id(PK, crypto.randomUUID) / projectId / title* / note(Markdown，可含 base64 图片) / repoPath / branch / status(todo・doing・done) / **swimlaneId（所在泳道，v5 新增；默认随 status 映射：todo→swim-todo、doing→swim-doing、done→swim-done）** / quadrant(do・schedule・delegate・eliminate，**仅数据兼容，UI 已弃用**) / seq(全局序号，前端 max+1 预生成、后端 app_meta.next_seq 写锁内收敛) / tag(`todo-<seq>`) / startDate・endDate(YYYY-MM-DD，可空) / blocker / archived / startedAt・doneAt(ms，可空) / commits(JSON 列) / **sortOrder（泳道内排序，v6 新增；拖拽后按 0..n 分配，重载保留）** / createdAt・updatedAt

**Project（DbProject，projects 表 15 列）**：id / name / projectDir / frontendDir / backendDir / frontendRepoUrl / backendRepoUrl / frontendRepoToken / backendRepoToken（v4 新增，明文本地库存储）/ productionBranch / branchRule(JSON，可空) / **swimlanes(JSON，可空，v5 新增；NULL → 前端预置默认三泳道)** / archived / createdAt / updatedAt

**BranchRule**：{ enabled, steps[] }；step = { id, from: BranchRole, action: checkout・merge, to: BranchRole, note }；BranchRole = production / develop / test / preview / custom

**Swimlane（泳道，v5 新增）**：{ id, name, status: todo・doing・done, sortOrder }——存于 projects.swimlanes JSON 列；**默认预置三泳道**：待办(swim-todo, todo) / 进行中(swim-doing, doing) / 已完成(swim-done, done)；语义：泳道 = 看板列、绑定状态（一个状态可有多个泳道），是「状态」的分组容器/视图，**状态为唯一事实源**

**CommitInfo**（snake_case，git 查询结果）：{ hash, subject, date(ISO 8601 committer date), branches[] }；落库形态 DbCommitInfo 为 camelCase，存 todos.commits JSON 列

**AppState ↔ DbState**：{ projects, todos }

### 4.3 SQLite Schema（USER_VERSION = 6）

```sql
projects(15 列): id PK, name, project_dir, frontend_dir, backend_dir,
  frontend_repo_url, backend_repo_url, production_branch,
  branch_rule TEXT(JSON, 可空), archived, created_at, updated_at,
  frontend_repo_token, backend_repo_token,            -- v4 新增
  swimlanes TEXT(JSON, 可空)                          -- v5 新增
todos(21 列): id PK, project_id, title, note, repo_path, branch,
  status DEFAULT 'todo', swimlane_id TEXT,             -- v5 新增（可空；按 status 映射默认泳道）
  quadrant DEFAULT 'schedule', seq, tag,
  start_date, end_date, blocker, archived, started_at, done_at,
  commits TEXT(JSON, DEFAULT '[]'), sort_order INTEGER NOT NULL DEFAULT 0,  -- v6 新增（泳道内排序）
  created_at, updated_at
  索引: idx_todos_project ON todos(project_id)
app_meta(v2): key PK, value        -- key='next_seq' 任务全局序号分配源
git_repo_cache(v3): repo_path PK, repo_exists, is_repo, current_branch,
  branches TEXT(JSON), error, fetched_at
```

迁移路径（db::init 幂等执行）：v1→v2 建 app_meta + 存量 tag/seq 清洗去重、最大序号写入 next_seq；v2→v3 建 git_repo_cache；v3→v4 projects 补两列 Token（幂等保护）；**v4→v5（泳道重构）**：projects 补 swimlanes 列、todos 补 swimlane_id 列（均为幂等 ALTER TABLE）；存量 todo 按 status 回填默认泳道 id（todo→swim-todo / doing→swim-doing / done→swim-done）；存量项目 swimlanes 为 NULL 由前端 normalize 预置默认三泳道。**v5→v6（排序持久化）**：todos 补 sort_order（幂等），存量按插入顺序（rowid）回填。

### 4.4 数据源解析

- 数据库位置 = **程序运行目录（exe 所在目录）下 `db-config.txt` 首行**（绝对路径）；指示缺失/为空 → 无数据源：`db_load_state` 返回 Ok(None)（前端空态并提示生成数据文件），`db_save_state` 拒绝并返回中文错误
- `ensure_db` 为预留能力（写指示文件指向 <exe_dir>/todo-git.db 并建库建表），当前未暴露命令
- WAL 模式；MCP server 同样回退 exe_dir，可用 `MCP_TODO_DB_CONFIG` 或 `--db-config <dir>` 覆盖
- ⚠ 历史遗留：前端 storage.ts 注释称「TODO_GIT_DB_PATH 环境变量优先」**与实现不符**（Rust 侧无此变量），重构勿被误导

### 4.5 存取语义

- **写（save_state）**：进程级 DB_RW_LOCK 写锁互斥 → 单事务**差异写**：UPSERT 变更行 + 差集删除（只删快照中已移除的行，未变行跳过，**不动快照之外的既有行**——多窗口增量保存互不覆盖）；updated_at 较新者胜；内含 **seq/tag 收敛**（写锁下从 app_meta.next_seq 取号，冲突待办重分配并改写 tag）与**提交全局去重**（库中既有优先、本批先到先得）；保存前校验分支规则；成功后清指纹缓存
- **读（load_state）**：读锁 + WAL 快照读双保险；`storage_fingerprint`（两表行数 + MAX(updated_at)）进程内缓存，未变直接复用（配合前端 2s 轮询开销趋近零）；**不用 PRAGMA data_version**（WAL 下跨连接不稳定）
- **前端归一化**（lib/normalize.ts 唯一入口）：normalizeTodo/Project 补默认（tag 兜底 `todo-<id前8位>` 等）；normalizeProject 补 defaultSwimlanes（swimlanes 缺失/为空 → 预置三泳道）；normalizeTodo 补 swimlaneId（缺失/悬空 → 按 status 映射该状态第一个泳道）；normalizeTodos 后执行 dedupeTodosCommits 历史脏数据修正；运行时 dedupeCommitsForTodo 归属保护
- **旧 JSON 迁移**：init_and_migrate 仅 core 保留供测试/参考，主路径 db::init 不触旧 JSON；旧文件只读保留

## 5. 接口设计

### 5.1 Tauri 命令（11 个）

| # | 命令 | 说明 |
| --- | --- | --- |
| 1 | git_info | 仓库校验+分支列表（走 SQLite 持久缓存，命中即回+后台 30s 节流刷新） |
| 2 | git_info_refresh | 强制刷新 git_info 缓存（app 专属，MCP 不暴露） |
| 3 | git_info_remote | 远端增强：本地分支 ∪ GitLab 远端分支（需仓库地址+Token；app 专属） |
| 4 | git_create_branch | 基于当前位置新建分支（不切换）；创建后 push -u 建立远端同名上游 |
| 5 | git_create_branch_from | 从切出源新建分支：先 fetch origin <切出源>，再基于 origin/<切出源> 切出（失败回退本地源）；校验分支名；创建后 push -u 建立远端同名上游 |
| 6 | git_checkout_branch | 检出目标分支（成功后失效分支缓存） |
| 7 | git_sync_commits | 按标记 `tag=todo-<n>` 全分支检索提交（log --all -F --grep） |
| 8 | git_commits_between | 时间窗抓取：committer date ∈ [since, until] 的指定分支提交（完成自动补录/按时间窗补录共用） |
| 9 | git_commit_info | 按短 hash 查询单条提交详情（手动添加） |
| 10 | db_load_state | 全量读取 { projects, todos }（读锁+指纹缓存；无数据源返回空） |
| 11 | db_save_state | 差异写落库（写锁+分支规则校验+**泳道归属校验**+seq 收敛+提交去重） |
| 12 | mcp_get_config | 读取 MCP 集成设置（启用开关+授权 Token；缺失回默认：启用 + `sk-GLOBAl_MCP_BY_ADMIN`） |
| 13 | mcp_set_config | 保存 MCP 集成设置（写 app_meta；禁用后 mcp-server 启动被拒） |
| 14 | db_check_version | 数据版本检查/升级（前端启动门禁）：执行 open_and_init（判定+备份+逐级迁移），返回 VersionReport（ok/upgraded/too_new/too_old + 双方版本 + 迁移步骤） |

统一约定：壳层薄转调 core::svc；错误 map_err 转中文 String；命令内不 panic。

### 5.2 MCP 契约（mcp-server，stdio）

- **9 tools**：git_info（直读，不经 app 缓存）+ git_create_branch / git_create_branch_from / git_checkout_branch / git_sync_commits / git_commits_between / git_commit_info + db_load_state / db_save_state（与同名 Tauri 命令同构；refresh/remote 为 app 专属不暴露）
- **3 resources**：状态/项目/待办只读视图（详见 mcp-design）
- 协议：手写逐行 JSON-RPC 2.0（initialize / tools / resources / ping），零 SDK；AppError→错误码映射（Invalid→-32602、其余→-32603）
- 安全：**启动认证**——mcp-server 启动时经数据文件读 app_meta 的 `mcp_enabled`/`mcp_token`：未启用 → 退出；`--token`/`MCP_TODO_TOKEN` 不匹配（默认 `sk-GLOBAl_MCP_BY_ADMIN`，设置页可改）→ 退出；无数据源 → 退出。**数据版本检查**——数据版本高于/低于软件支持范围 → 拒绝启动（stderr 提示「数据版本不兼容…」）；兼容升级在启动时自动执行（硬备份 + 逐级迁移）。`MCP_TODO_READONLY=1` 仍拒绝全部写工具（与 Token 正交）。stdout 仅协议帧、日志走 stderr
- **AI 打标**：`db_save_state` 落库前对比库中现状——新建 todo/project 强制 `createdBy=ai`（+todo `aiCoordinated=true`）；修改已存在 todo 置 `aiCoordinated=true`（`createdBy` 保持）；卡片据此展示「AI 创建 / AI 协助」标记

### 6.2 状态管理与持久化

- zustand v5 唯一 store（lib/store.ts，9 action + loaded）；视图与数据解耦：页面只经 store action 改状态，**拖拽落库必须经 commitOrder / patchTodo，禁止只改本地状态**
- 写链：store action → subscribe → **writeChain 串行队列** → saveState → invoke db_save_state（浏览器模式 saveState 直接返回）
- 外部同步：startExternalSync 每 2000ms 轮询 + window focus 立即 syncExternalNow → 全量重读（后端指纹缓存零开销）→ 与内存 JSON 对比 → 不同则**磁盘优先整体覆盖**

### 6.3 git 信息三层缓存

前端 lib/git.ts：60s TTL 内存缓存 + 单飞去重 + 路径大小写折叠 + 同步 peek（peekGitInfo / gitInfoCached / invalidateGitInfo）→ 后端 svc/repo_cache：git_repo_cache SQLite 持久缓存（命中即回 + 后台 30s 节流刷新）→ App 启动后 startGitCacheWarm 60s 预热全部仓库路径。分支写操作成功后前后端双失效。GitLab API 失败静默回退本地分支。

### 6.4 关键组件

- **SwimlaneBoard（泳道看板）**：**列 = 泳道、行 = 待办**。横向泳道列容器（列头 = 泳道名 + 计数 + 操作，含「管理泳道」入口）；dnd-kit（PointerSensor 激活距离 6px，DragOverlay 浮层）：泳道内纵向拖拽排序 + **跨泳道拖拽（= 修改 swimlaneId，联动同步 status）**；commit() 经 store commitOrder / patchTodo 落库，禁止只改本地状态；「管理泳道」对话框：增删 / 改名 / 拖排序 / 绑定状态（新增必须选状态），删除泳道时其下待办归入同状态剩余第一个泳道
- **TodoDetailPage**：RHF + zod（与后端 validate_branch_name 同规则）；中间标题+WYSIWYG Markdown 备注，右侧字段栏（代码目录 Select / 仓库状态条 / BranchSelect 可搜索、生产置顶、当前标注 / 新建分支（切出源默认生产分支）/ **泳道 Select（该项目泳道列表，按绑定状态分组，默认预选当前状态第一个泳道）** / DateRangePicker / 卡点）；代码目录变化 peek 命中即应用，自定义路径 300ms 防抖 + reqSeq 竞态守卫；配置 Token 走 gitInfoRemote

## 7. 后端设计要点

- **workspace 三分**：壳 crate 只注册命令+转调；core 纯逻辑可独立单测、被 MCP 复用；mcp-server 独立进程

- lib crate 名含 `_lib` 后缀（Windows Cargo#8519），勿改名；main.rs 的 `windows_subsystem = "windows"` 注释勿删

## 8. 核心流程

### 8.1 启动加载
App.tsx useEffect → initAppStore() → loadState → invoke db_load_state → resolve_db_path（无数据源→空态）→ db::open(WAL)/init(v6 迁移) → 指纹缓存命中即回/全量 SELECT → normalize（补默认+泳道回填+提交去重兜底）→ startExternalSync(2s 轮询+focus 同步) → startGitCacheWarm(60s 预热)

### 8.2 新建分支（从切出源）
详情页勾选「新建分支」→ 切出源默认生产分支（可改选）→ 保存时后端 fetch origin <切出源> → 基于 origin/<切出源> 切出（无远程/拉取失败回退本地源并注明；创建用 `--no-track` 阻止 git 自动把上游指向切出源）→ `git push -u origin <新分支>` 推送远端同名分支并建立上游（push 失败仅告警，不阻断保存）→ **不切换**当前工作分支 → 失效分支缓存

### 8.3 提交关联
「开始」记 startedAt → 提交到绑定分支（可带 [todo-N]）→「完成」记 doneAt 并 autoRecaptureOnDone：git_commits_between(createdAt, doneAt) → mergeCommits + dedupeCommitsForTodo 全局去重 → patchTodo 落库；「按时间窗补录」恒为 [createdAt, 最新]；「同步提交」按 tag 全分支检索。上线时正常合分支；非正常上线从提交记录复制 hash 做 cherry-pick（新提交仍带原标记，可再同步）。

### 8.4 MCP 设置与 AI 任务登记
- 设置页「MCP 集成」：启用/禁用开关（默认开）+ 授权 Token（默认 `sk-GLOBAl_MCP_BY_ADMIN`）→ `mcp_set_config` 写 app_meta；MCP server 每次启动读取校验（见 §5.2）。
- AI 登记路径：AI agent 读 `todo-kanban-register` skill → MCP server（stdio，携带授权 Token）→ `git_info` 校验仓库 → `db_load_state` 按 projectDir/frontendDir/backendDir 匹配项目（路径归一化）→ 命中登记 todo / 未命中先建项目再登记（`db_save_state`，AI 标记自动打）。

### 8.5 数据版本升级（独立 upgrade 分包）
- **版本模型**：数据版本 = `PRAGMA user_version`；软件内置 `CURRENT_VERSION`（=USER_VERSION，当前 7）与 `MIN_SUPPORTED_VERSION`（当前 1），编译打包进软件——常量集中在纯配置库 `todo-kanban-config` 分包，升级引擎在 `todo-kanban-upgrade` 分包。
- **判定**：data_version > CURRENT → **TooNew 拒绝**「数据由更高版本创建，请升级软件」；data_version < MIN → **TooOld 拒绝**「请先安装中间版本」；MIN ≤ v < CURRENT → **兼容升级**（硬备份 → 逐级迁移 vX→…→最新）。
- **升级入口**：`core db::open_and_init(path, backup_dir)`（open → 建表 → 判定/备份/迁移/报告）为 app 与 MCP 唯一入口；`db_check_version` 命令供前端启动门禁。
- **备份**：迁移前 `wal_checkpoint(TRUNCATE)` 后，将 db 主文件**硬复制到程序运行目录 `backup/`**（`<stem>-v<from>-<时间戳>.db`，保留最近 10 份）。
- **前端**：App.tsx 启动先 `db_check_version`——too_new/too_old → 全屏 `VersionBlockedPage`（不进主界面，展示双方版本）；upgraded → toast「数据已从 vX 升级到 vY」。详见 ADR-011。

## 9. 关键架构决策（ADR 摘要）

> 本表为摘要；每项决策的完整记录（背景 / 备选方案 / 后果）见 `docs/decisions/`（ADR-001 ~ ADR-011；泳道两项见 ADR-009 / ADR-010）。

| 决策 | 理由 |
| --- | --- |
| HashRouter 而非 BrowserRouter | Tauri 本地协议下路由可用（勿改回） |
| zustand 唯一 store + writeChain 串行写 | 防并发写乱序；外部变更可安全整体覆盖 |
| 系统 git CLI / 系统 curl | 零 crate 依赖；输出格式统一；curl -k 兼容内网自签 |
| 命令薄壳 + core 纯逻辑 workspace | core 无 tauri 依赖可独立单测、被 MCP 复用 |
| quiet_command + CREATE_NO_WINDOW | release GUI 壳下子进程防闪黑框 |
| JSON → SQLite（rusqlite bundled） | 事务原子写替代 tmp+rename；索引/查询扩展性 |
| 数据源 = 运行目录 db-config.txt 指示文件 | 数据库位置自由指定/多数据文件；无指示→空态 |
| app_meta.next_seq + 写锁内取号 | 多窗口并发下 todo-<n> 全局唯一 |
| 提交唯一性全局去重 | 时间窗/标记/手动三路径收敛，避免重复归属 |
| 归档不展示（无恢复 UI） | 外部改库可恢复，2s 轮询感知（有意取舍） |
| 泳道看板替换四象限（列=泳道绑状态、行=待办、项目自定义增删） | **状态是唯一事实源**、泳道只是状态的分组容器；拖拽跨列 = 泳道+状态联动，避免双真相；项目自定义列可适配实际流程；quadrant 字段保留仅数据兼容 |
| 泳道内排序持久化（todos.sort_order，v6） | 拖拽排序落库（0..n 分配 + updatedAt 刷新）；重载按 sortOrder 还原，同序按 createdAt 兜底 |
| 补录时间窗从 createdAt 起 | 从创建任务开始收录，不依赖是否点过开始 |
| 浏览器模式无存储 | 桌面端 SQLite 是唯一存储（旧 localStorage 双通道已移除） |
| MCP 手写逐行 JSON-RPC（零 SDK） | 少依赖约定；stdout 仅协议帧、日志走 stderr |
